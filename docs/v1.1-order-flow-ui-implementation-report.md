## 2. 商品選択 UI（07.4）

対象: `/pets/[petId]/album/[albumId]/product`

### 構成

1. ヘッダー「フォトブックを注文」+ `OrderFlowSteps`（step 1）
2. 完成フォトブックの大きなモック（album cover）+ コピー
3. 3プラン比較（Standard / Premium / Premium Plus）
4. ページ数選択
5. 合計金額 + CTA「注文内容を確認する」

### 比較表示項目

- 商品名 / 価格 / サイズ / カバー / ページ数 / 選択状態

### 意図的に入れていないもの

- ギフトラッピング / メッセージカード（現行カタログ・価格ロジックに未存在）

---

## 3. Checkout UI（08.1 / 08.2）

対象: `/pets/[petId]/album/[albumId]/checkout`

### 08.1 注文内容の確認

- 上部に表紙モック + アルバムタイトル
- 商品名 / サイズ / ページ数 / カバー
- 「仕様を変更する」→ product へ戻る
- 配送先入力（フォームロジック維持、羅列感を抑えた余白・見出し）
- 配送方法
- 金額内訳（商品小計 / 送料 / 合計）

### 08.2 お支払い（UCHINOCO 内の直前画面）

- 「クレジットカード」を選択済みとして表示
- Stripe Checkout へ進む旨を明記
- Apple Pay / Google Pay 等は Stripe 画面で選択可能である旨を注記
- **Stripe Elements への置換なし**（現行 Checkout Session 維持）
- CTA:「支払いへ進む」（Stripe 遷移の意味に合わせた文言）

### 維持したロジック

- `validateAddress` / FormData 送信（PII を URL に載せない）
- `createCheckoutSession` Server Action
- 写真枚数超過時の hard block
- `?cancelled=1` 復帰メッセージ

## 4. Order Complete UI（08.3）

対象: `/pets/[petId]/album/[albumId]/order/[orderId]`（`status = paid`）

### 構成

1. `OrderFlowSteps`（step 3）
2. 大きな感謝メッセージ（`getOrderStatusMessage("paid")` = 「ご注文ありがとうございます」）
3. snapshot 表紙の大きなモック
4. `OrderProductionProgress`（制作進行）
5. 「注文履歴を見る」
6. 注文サマリー
7. `order_photos` プレビュー（snapshot）
8. 「写真を追加する」導線

### 進行表示の正直さ（Provider 未接続）

`print_jobs` は RLS で `authenticated` / `anon` から REVOKE されており、注文画面から取得しない。

paid 時の表示:

- ご注文受付 → 完了
- **制作準備中** → 現在（「制作中」までは断定しない）
- 発送準備 / お届け → 未着手のまま

コピー例:

- 「ご注文を受け付けました」
- 「ただいま制作準備中です」

実際に shipped でないのに「発送準備中」等を確定表示しない。

### その他 status

| status | UI |
|---|---|
| pending | PROCESSING バナー + 再読み込み |
| failed | FAILED バナー +「再注文する」→ `/product` |
| cancelled | CANCELLED バナー +「注文内容へ戻る」→ `/product` |

## 8. Typography

## 10. Spacing

- `app-page-order`: page top / section 間 / CTA 前の余白を拡大

## 11. Border / Card

- カードを増やしすぎない
- 情報グループは divider / whitespace / typography で整理
- 必要なまとまりのみ: 商品選択・注文サマリー・status / production block
- 角丸は控えめ（`rounded-lg` / `rounded-xl` 中心）
